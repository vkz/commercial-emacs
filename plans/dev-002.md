Goal: make clemacs bring-up faster, more repeatable, and less “rediscovery-prone”
across multiple agents and sessions.

1) Extract a single “Agent Playbook” doc (keep `AGENTS.md` short): add `plans/agent-playbook.md` with the operational runbook (commands + interpretation + escalation paths), and in `AGENTS.md` link it right under “Guiding documents”.

2) Add an explicit decision tree to `AGENTS.md` (or the playbook), centered on the new tools:
   - Loader fails → run `mise run clemacs:report:first-failure -- --mode startup-check` → set checkpoint to “recommended max-forms” → implement missing primitive or ported rewrite → add microtest + compat note if semantic → rerun `clemacs:test:contract --level elisp-core`.
   - Upstream ERT regression → confirm it’s in must-pass list → if real gap, move to `known-fail` *with date+reason* only if temporary → otherwise implement fix → rerun `clemacs:test:contract --level check`.
   - Checkpoint work feels unstable → run `mise run clemacs:bisect:file -- --file … --manifest …` and use its max passing value.

3) Create 3 repo-specific skills (small, high-leverage) and tell agents when to use them:
   - `clemacs-port-loop`: the standard “tight loop” (run gates, read reports, update checkpoints, add breadcrumbs).
   - `clemacs-loader-debug`: interpreting first-failure reports, inventory mapping, when to bisect, when to enable `CLEMACS_LOAD_DEBUG_FILE`.
   - `clemacs-ert-bringup`: monotonic expansion protocol for `ert-upstream.tests`, proper `known-fail` hygiene (incl XPASS handling), batching strategy.

4) Wire skill triggers into docs: in `AGENTS.md`, add a “When to use which skill” section mapping common tasks (“adding a new startup file”, “raising a checkpoint”, “new semantic shim”, “ERT xfail/xpass”) to the skill name + 1–2 commands.

5) Make artifacts first-class and comparable across sessions: standardize outputs under `build/clemacs/reports/` and say “always attach these artifacts” in bug reports/PRs.

6) Add a “no-rediscovery checklist” gate: require (a) microtest update when semantics change, (b) compat report update when diverging, (c) manifest monotonic rule, (d) contract run before declaring done.

7) Add one “agent onboarding” command sequence (copy/paste): `mise run clemacs:test:contract -- --level elisp-core && mise run clemacs:report:progress`, plus “if it fails, run first-failure”.

8) Instruct agents (in `AGENTS.md`) to introspect: when they get stuck or rediscover a trick, add exactly one new bullet to the playbook or one new helper subcommand/task—keep the system evolving but minimal.
